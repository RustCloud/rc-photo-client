# Время создания и изменения файла от клиента

**Где:** сервер RustCloud (`crates/files`, `crates/plugin-api`, `crates/server`) и плагин «Фото» (rc-photo).

## Проблема

Если при загрузке клиент передал время файла, сервер должен хранить его как метаданные файла. Плагины
должны видеть это время.

Сейчас фото без EXIF (скриншоты, картинки из мессенджеров, часть видео) в галерее и в историях
«в этот день» получают дату загрузки, а не дату, когда файл появился на телефоне. Загрузили в
ноябре скриншот, сделанный в марте, — в галерее он стоит в ноябре.

## Как сейчас

| Время | Где хранится | Можно передать при загрузке | Кто видит |
|---|---|---|---|
| Изменения (mtime) | `nodes.modified_at` | да: `?mtime=` в `POST …/upload`, `mtime` в `POST …/uploads`, `PATCH {modified_at}` | API (`Node.modified_at`), панель, WebDAV `getlastmodified`, ZIP |
| Создания | `nodes.created_at` | **нет**, всегда время загрузки | API, WebDAV `creationdate` |
| Плагинам | WIT `record node` | — | **только `updated-at`**, то есть время последней правки на сервере |

Подробности:

1. Сервер принимает `mtime`, проверяет его в `check_mtime` и пишет в `modified_at`
   (`crates/files/src/service.rs:334`, `uploads.rs:138`). Эта часть работает.
2. Время создания клиент передать не может. `created_at` ставится в `now` (`service.rs:1020`).
3. В `record node` (`crates/plugin-api/wit/app.wit:119`) есть только `updated-at`. `file_node` в
   `crates/server/src/app_routes.rs:899` заполняет его из `node.updated_at`. До плагинов не доходят
   ни `modified_at`, ни `created_at`.
4. Плагин «Фото» пишет `node.updated_at` в `Entry.modified` (`src/media.rs:134`, `:293`). Если в
   EXIF нет даты съёмки, дату берёт оттуда: страница галереи (`ui/app.js:610`) и истории
   (`src/stories.rs:132`).

Приложение для Android уже отправляет `mtime` с каждой загрузкой. Вся неверная дата появляется на
сервере.

## Что предлагаем

### 1. Сервер: время создания от клиента

- Новый необязательный параметр `ctime` в том же формате, что `mtime` (секунды Unix или RFC 3339),
  с той же проверкой `check_mtime`:
  - `POST /api/v1/files/{folder}/upload?…&ctime=<время>`;
  - `ctime` в теле `POST /api/v1/files/{folder}/uploads` (его стоит хранить в сессии загрузки, как
    `mtime`);
  - `PATCH /api/v1/files/{id}` с `{created_at?}` — поправить уже загруженное.
- Хранить в **новом** столбце, например `nodes.file_created_at` (nullable), а не переписывать
  `created_at`. `created_at` остаётся временем появления файла на сервере, на нём завязана логика:
  объединение частых сохранений в одну версию (`versions.rs:167`) сравнивает его с `now`.
- В `Node` отдавать новое поле. Предлагаем назвать его `born_at`: «когда файл создан на
  устройстве; `created_at`, если клиент не передал». Это по аналогии с `modified_at`, который
  берёт `updated_at`, если клиент время не передал.
- WebDAV `creationdate` брать из нового поля.
- При `overwrite=true`, если файл уже есть, `ctime` не менять: у файла новое содержимое, но
  создан он раньше. Применять `ctime` только к новому файлу.
- Если передан `ctime` без `mtime`, `modified_at` можно оставить пустым, как сейчас.

Неизвестные параметры сервер сейчас игнорирует (`UploadParams` и `StartUpload` без
`deny_unknown_fields`). Значит, клиенты могут начать отправлять `ctime` заранее, и старый сервер
ничего не сломает.

### 2. Сервер: время файла для плагинов

- В `record node` добавить:
  ```wit
  /// RFC 3339. When the content was changed, as the uploading client said;
  /// `updated-at` if it didn't.
  modified-at: string,
  /// RFC 3339. When the file was created on the client's device;
  /// the server's `created-at` if the client didn't say.
  born-at: string,
  ```
  Заполнить их в `file_node` (`app_routes.rs:891`).
- **Совместимость.** Новое поле в `record` меняет его тип в component model, и плагины, собранные
  со старым `app.wit`, перестанут загружаться. Варианты:
  - а) новая версия интерфейса `files` рядом со старой, хост поддерживает обе;
  - б) пересобрать все плагины вместе с сервером и поднять минимальную версию API в манифесте.

  Если плагины ставят только из своего репозитория, проще вариант б.

### 3. Плагин «Фото»

- Дата файла без EXIF: `born-at`, а если его нет — `modified-at`. В `Entry` можно положить оба или
  одно поле `modified` = `born-at`, чтобы не менять формат шардов и страницу.
- После обновления один раз пройти все папки (`media::rescan`). Файлы с тем же ETag идут по
  короткой ветке `src/media.rs:127`, которая обновляет только имя, папку и время, без повторного
  разбора.
- Порядок дат для галереи и историй не меняется: сначала EXIF (`taken`), потом время от клиента.

### 4. Клиент Android (сделаем сами, когда будет п. 1)

Сейчас приложение шлёт в `mtime` дату съёмки из MediaStore, а если её нет — `DATE_MODIFIED`. После
п. 1 будет слать:
- `ctime` = `DATE_TAKEN`, иначе `DATE_ADDED`;
- `mtime` = `DATE_MODIFIED`.

Уже загруженные файлы приложение поправит через `PATCH {created_at}`: нужные даты у него есть в
локальной базе бэкапа.

## Как проверить

1. Загрузить файл с `?mtime=1710000000&ctime=1709000000`. В ответе `modified_at` должен быть
   2024-03-09, `born_at` — 2024-02-27, `created_at` — сейчас.
2. WebDAV `PROPFIND`: `creationdate` = 2024-02-27, `getlastmodified` = 2024-03-09.
3. Загрузить PNG без EXIF с `ctime` в прошлом. В галерее плагина он должен оказаться на дату
   `ctime`, а не на сегодня.
4. `overwrite=true` с другим `ctime` для существующего файла: `born_at` не меняется.
5. `ctime` в будущем дальше `MTIME_AHEAD` или до 1970 — `400 INVALID_MTIME` (или отдельный
   `INVALID_CTIME`).
