# rc-photo-client — план

Приложение для телефонов в духе Google Фото поверх RustCloud. Google Фото — источник хороших
решений для интерфейса, а не образец для копирования: сервер, возможности и внешний вид свои.

- **Файлы** (загрузка с телефона, оригиналы, корзина) приложение берёт из API облака `/api/v1/…`.
- **Галерея** (лента, избранное, лица, истории, поиск по описанию, похожие, текст на фото)
  приходит из плагина [rc-photo](../r-image): маршруты `/app/rc-photo/api/…`.

Документы, на которые опирается план:

- сервер: `../rustcloud/docs/api/{auth,files,grants,apps,app-passwords}.md`, `../rustcloud/docs/dev/plugins.md`;
- плагин: `../r-image/README.md`, `../r-image/src/api.rs`, `../r-image/src/index.rs`;
- клиент синхронизации: `../rc-client/README.md`, раздел «Аккаунт телефона (Android)».

## 1. Решения (зафиксированы 2026-11-22, не пересматриваем)

| Вопрос | Решение |
|---|---|
| Что делаем | Только приложение для телефонов. Сначала Android, потом iOS. Десктоп не делаем: там есть веб-страница плагина и синхронизация rc-client. |
| Стек | **Flutter** (Dart). Нативный код (Kotlin, позже Swift) только там, где без него нельзя: аккаунт rc-client (`AccountManager`), мелочи MediaStore. |
| Репозиторий | `github.com/RustCloud/rc-photo-client`, пушим прямо в `main`. CI — GitHub Actions, релизы — GitHub Releases. |
| Другие репозитории | Плагин, сервер и rc-client не меняем сами. Что там нужно, описываем в [docs/requests.md](docs/requests.md); пользователь с разработчиками делает обновление. Приложение по возможности обходится без этих изменений и узнаёт новые возможности по ответам сервера. |
| Синхронизация | **Односторонняя: телефон → облако** (резервная копия). Двусторонняя — задача rc-client. |
| Вход | Аккаунт rc-client, если он установлен (Android), иначе свой вход OAuth 2.0 + PKCE через браузер. Пароль приложения — будущий вопрос 1. |
| Интерфейс | Ориентир — Google Фото: лента с группами по дням, щипок меняет сетку, просмотр с листанием, «Освободить место», истории. Material 3, тёмная тема, русский и английский. |
| Минимальные версии | Android 8.0 (`minSdk 26`), `targetSdk` и `compileSdk` — по умолчанию Flutter (36 во Flutter 3.44). iOS — когда дойдём. |
| Сборка и тесты | buildserver, Docker-образ `ghcr.io/cirruslabs/flutter` с зафиксированной версией. Эмулятора нет (нет `/dev/kvm`), поэтому: `flutter test` (логика, виджеты, golden-скриншоты), интеграционные тесты API на чистом Dart против настоящего rustcloud, вживую — на телефоне пользователя. |
| `applicationId` | `com.rustcloud.photos` (схема входа `com.rustcloud.photos:/callback`). Ключ подписи — будущий вопрос 2. |

## 2. Что уже есть на сервере — проверено (фаза 0)

Проверено 2026-11-22 скриптом [tools/api_check.py](tools/api_check.py) (`sh tools/api-check.sh` на
buildserver) против `ghcr.io/rustcloud/server` коммита 60e0e59 и rc-photo 0.8.0: **22 из 22**.

| Что нужно приложению | Чем это дать | Результат проверки |
|---|---|---|
| Вход | OAuth 2.0 + PKCE (`/api/v1/auth/authorize`, `/token`) | `redirect_uri=com.rustcloud.photos:/callback` принимается, код меняется на токены. Access-токен — 10 минут. Refresh меняется при каждом обмене; повтор старого в первые 30 с даёт новую пару и сессию не рвёт. |
| Вход без своего логина | Аккаунт rc-client (`com.rustcloud.account`, `AccountManager`) | Приложению с тем же ключом подписи токен выдаётся без вопросов, другим — после согласия. Выдаётся только access-токен. Не проверено (нужен телефон). |
| Маршруты плагина с токеном | `/app/rc-photo/api/…` + `Authorization: Bearer` | Работают: `state`, `links`, `stream`. |
| Индекс галереи | `state.shards` — 64 ссылки на `index/<00–3f>.json` | Скачиваются без заголовков, `ETag` + `If-None-Match` → `304`. **≈ 500 Б на фото, ≈ 5 МБ на 10 тыс.** — постраничная выдача не нужна. Ссылки живут 12–13 ч и пропадают при перезапуске сервера. |
| Миниатюры и превью | `POST /api/links` (`{items:[{id, kind}]}`, до 1000) | Ссылки скачиваются без заголовков. Запасной путь сервера `/api/v1/files/{id}/thumbnail` работает. |
| Видео | `GET /api/stream/<id>?mode=copy\|h264` → `{url}` HLS | Работает. |
| Загрузка | `POST /api/v1/files/{folder}/upload?name=&mtime=` и по частям `/uploads` → `PUT ?offset=` → `finish {sha256}` | Обе работают, докачка по `received` тоже. Повтор имени → `409 NAME_TAKEN`. |
| Сравнение по хэшу | `Node.etag` и `Entry.etag` | Оба равны sha256 содержимого (301 из 301). |
| Папка плагину | `POST /api/v1/grants {app_id:"rc-photo", node_id, write:true, kind:"standing"}` | Работает с токеном приложения; папка сразу появляется в `state.folders`. |
| Индексация | Сервер ставит плагину задачу по `file.created` | 301 фото попали в индекс за 13 с (без ИИ-анализа: он идёт отдельно, `progress.clip`). |
| Новое в облаке | `GET /api/v1/files/changes?cursor=` (+ SSE `changes/watch`) | Работает. |

Найдено при проверке:

- **Дата фото без EXIF.** `Entry.modified` берётся из `updated_at` (время загрузки), а не из
  переданного `mtime`, потому что у плагина в WIT нет `modified_at`. У скриншотов и картинок из
  мессенджеров дата в ленте будет датой загрузки. Запрос — [docs/requests.md](docs/requests.md#1),
  а пока приложение показывает для своих загруженных файлов дату с телефона (она есть в локальной базе).

Последствия для архитектуры:

- **Загрузка идёт мимо плагина.** Приложение кладёт файл в выданную папку, сервер сам ставит
  плагину задачу, фото появляется в индексе. Если плагин выключен, резервная копия всё равно работает.
- **sha256 даёт дедупликацию** (после переустановки, если фото уже загружено через веб) и склейку
  локальных и облачных фото в одной ленте.
- **Индекс целиком на телефоне.** 64 шарда, перекачиваются только изменённые (`ETag`).

## 3. Устройство приложения

```text
lib/
  api/      клиент сервера и плагина на чистом Dart (без Flutter): модели, ошибки, вход, загрузка.
            Работает и в `dart test` против настоящего rustcloud.
  auth/     вход: PKCE через браузер, аккаунт rc-client, хранение токенов
  db/       локальная база (drift, SQLite): индекс галереи, локальные медиа, очередь загрузки
  sync/     резервная копия: сканер MediaStore, планировщик, загрузчик
  ui/       экраны: вход, лента, просмотр, резервная копия, настройки …
android/    нативное: AccountManager, MediaStore
test/       логика и виджеты; test/api_live/ — против сервера (по переменной RC_TEST_URL)
tools/      проверки на buildserver
```

Пакеты: `dio` (сеть, перехват 401), `drift` + `sqlite3_flutter_libs`, `flutter_riverpod`,
`cached_network_image` (кэш по ключу `id+etag`, не по URL: ссылки меняются), `video_player`
(ExoPlayer, HLS), `flutter_web_auth_2` (Custom Tabs), `flutter_secure_storage` (Keystore),
`photo_manager` (MediaStore/PhotoKit), `workmanager` (фон). Набор уточняется по ходу, без лишнего.

## 4. Фаза 1 — каркас приложения

## 5. Фаза 2 — вход и сервер

- Экран «Адрес облака» → `GET /api/v1/info` (это RustCloud? есть миниатюры?) и
  `GET /app/rc-photo/api/state` (плагин установлен и включён?) → вход.
- **Через rc-client (Android):**
  - `AccountManager.getAccountsByType("com.rustcloud.account")`, затем `getAuthToken(…, "api")`
    через platform channel;
  - в манифесте `<intent-filter>` с `com.rustcloud.action.USE_ACCOUNT`;
  - токен на 10 минут; когда кончается — просить снова; `KEY_INTENT` открывает экран входа клиента.
- **Свой вход:**
  - Custom Tabs → `authorize` → `com.rustcloud.photos:/callback` → `token`;
  - токены в `flutter_secure_storage` (Android Keystore);
  - обновление токена одно на всё приложение (mutex); новый refresh записывается до любого
    другого запроса.
- Общий перехватчик dio: 401 → обновить токен → повторить запрос один раз.
- «Выйти»: `POST /api/v1/auth/logout` (только при своём входе) и очистка базы.
- Тесты: фальшивый сервер (ротация refresh, параллельные 401, повтор после обрыва) и вход против
  настоящего rustcloud на buildserver.

## 6. Фаза 3 — галерея (только чтение)

- `state` → шарды с `If-None-Match`, `ETag` каждого шарда в базе. Изменённые шарды разбираются
  в таблицу `entry` (индексы по дате и папке).
- **Лента:** сетка с группами по дням и месяцам, быстрая прокрутка с подписью месяца, щипок
  меняет число колонок (3/5/7), как в Google Фото.
- **Миниатюры:** ссылки пачками до 1000 через `POST /api/links` для видимого диапазона и запаса
  вокруг; кэш по `id+etag`; на 404 — запросить ссылку заново.
- **Просмотр:** превью с зумом, листание; снизу сведения (дата, камера, объектив, экспозиция,
  место); видео — оригинал по ссылке, если телефон не играет — HLS `stream?mode=h264`.
- Обновление: при открытии и по `changes/watch`, пока приложение на экране, не чаще раза в 30 с.
- `progress` из `state`: «Обрабатывается N фото».

## 7. Фаза 4 — резервная копия (телефон → облако)

- **Что копировать.** Альбомы телефона: по умолчанию «Камера», остальные по выбору. Разрешения:
  `READ_MEDIA_IMAGES`/`READ_MEDIA_VIDEO` (13+), частичный доступ 14+ (объяснить, что копируются
  только выбранные), **`ACCESS_MEDIA_LOCATION`** — без него Android вырезает GPS из EXIF.
- **Куда.** Папка облака по выбору; по умолчанию — будущий вопрос 3. Если её нет в `folders`
  плагина — выдать через `POST /api/v1/grants` с `write:true`, предупредив. Без подпапок по датам.
- **Когда.** `workmanager`: раз в 15 мин и по триггеру на новые медиа (нативный
  `addContentUriTrigger`); условия «только Wi-Fi» (по умолчанию для видео), «только при зарядке».
  Долгая загрузка — foreground с уведомлением (`dataSync`; у Android 15 лимит 6 ч в сутки,
  работа прерывается и продолжается).
- **Как.**
  - Таблица `local_media`: `media_id`, `size`, `date_modified`, `sha256`, `remote_id`, `state`
    (новый, загружается, загружен, ошибка), `upload_id`, `received`. sha256 — потоком при
    отправке, повторно — только если изменились `size` или `date_modified`.
  - До 16 МиБ — одним запросом, больше — по частям по 8 МиБ с докачкой; `upload_id` в базе.
  - `mtime` из `DATE_TAKEN`, иначе `DATE_MODIFIED`.
  - `409 NAME_TAKEN`: файл с таким именем и тем же `etag` — уже загружен; другой — `имя (2).jpg`.
  - Первый запуск и переустановка: один раз прочитать `children` папки и сопоставить хэши.
  - Ошибки: `413 QUOTA_EXCEEDED` → стоп и уведомление; `429 TOO_MANY_UPLOADS` → подождать;
    сеть → повторы с нарастающей паузой.
- **Экран «Резервная копия»:** вкл/выкл, альбомы и папка, сколько осталось и что идёт, ошибки,
  «Синхронизировать сейчас».
- **Тесты:** планировщик и состояния — с фальшивым MediaStore и сервером; загрузка по частям,
  обрыв, `CHECKSUM_MISMATCH`, дедупликация — против настоящего rustcloud.

## 8. Фаза 5 — одна лента: телефон и облако

- В ленте и локальные, и облачные фото; совпадение `sha256 == Entry.etag` — одна карточка.
- Значки: «только на телефоне», «загружается», «только в облаке».
- Локальное фото открывается с телефона, без сети.
- **«Освободить место»:** удалить с телефона то, что точно есть в облаке (хэш совпал, файл в
  индексе), через системный запрос удаления.

## 9. Фаза 6 — возможности плагина

## 11. Будущие вопросы (разработку не блокируют)

1. **Пароль приложения.** Он открывает только `/app/<id>/` и `/dav/`, а `/api/v1` — нет
   (`app-passwords.md`). С ним работала бы галерея и загрузка через WebDAV `PUT` (без докачки
   по частям), но не выдача папки плагину. Варианты: не поддерживать; поддержать как запасной
   вход с ограничениями; попросить сервер открыть паролю приложения нужную часть `/api/v1`.
   Нужно решить до фазы 2.
2. **Ключ подписи** общий с rc-client (`RustCloud/client`)? С общим ключом аккаунт телефона
   выдаёт токен без вопроса. Пока — debug-ключ. Решить до первого релиза.
3. **Папка по умолчанию:** `Фото/<имя устройства>` или общая `Фото/Камера`. До фазы 4.
4. **Удаление.** Удаление на телефоне облако не трогает — подходит, или нужна настройка «удалять
   и в облаке»? И обратное: «в корзину» в приложении для фото, которое есть и на телефоне, —
   удалять ли и с телефона? До фазы 5.
5. **Альбомы мессенджеров и скриншоты** по умолчанию выключены — так? До фазы 4.
6. **Видео по мобильной сети** — по умолчанию только Wi-Fi; нужен ли лимит по размеру? До фазы 4.
7. **Карта:** нужна ли, и чьи тайлы (OSM или свой сервер). До фазы 6.
8. **iOS:** когда начинать и есть ли Apple Developer-аккаунт (подпись, TestFlight).
9. **Лицензия** репозитория (у плагина и сервера своя — брать ту же?). До первого релиза.
10. **Название и иконка.** Сейчас «RustCloud Фото» / «RustCloud Photos» и иконка Flutter по умолчанию.
